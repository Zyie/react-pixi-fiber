# react-three-fiber on pixi-3d: feasibility

Date: 2026-11-05. Sources: r3f `v10`, pixi-3d `main` and pixi.js `dev` under `.repos/`, plus the spike in `spike/`.

Path shorthand used below:

- `r3f/` = `.repos/react-three-fiber/packages/fiber/src/`
- `r3f-types/` = `.repos/react-three-fiber/packages/fiber/types/`
- `p3d/` = `.repos/pixi-3d/src/`
- `pixi/` = `.repos/pixijs/src/`

## 1. Verdict

**Feasible. It needs a list of pixi-3d changes to reach good parity, and no changes to r3f core.** The spike ran r3f v10's core byte-for-byte unchanged on pixi-3d. That covers the reconciler, store, scheduler loop, events, `<Canvas>` and Suspense loaders. A support module of about 460 lines filled the renderer seam, and all 9 spike tests pass, including a pixel check and real pointer events. The hard part is not the React layer. It's the three.js surface that apps touch directly: imperative math and colour calls, three-shaped types, drei, three loaders, environment maps and how pixi-3d's PBR shades metal. "Swap the import and keep working" holds for simple scenes that use r3f intrinsics and hooks. It doesn't hold for typical production apps, because they import `three` and `@react-three/drei` directly.

### Shortcuts in the spike that aren't production-ready

- **Kind:** it reports `kind: 'webgpu'`. Core's only runtime branch is `support.kind === 'webgl'` (`r3f/core/renderer.ts:303`), so `kind: 'pixi'` takes the same async-init path without falsely enabling the occlusion gate (`r3f/core/visibility.ts:83`). The closed union is a type issue only (`r3f-types/provider.d.ts:59,72-75`).
- **Camera matrices are a frame stale:** the `projectionMatrix`/`matrixWorldInverse` getters return pixi-3d's `projection`/`view`, which are rebuilt only during render (`p3d/scene/cameras/Camera3D.ts:186-233`). The frustum lags a frame and is identity before the first render. Compute them from `computeProjection(aspect)` (`Camera3D.ts:525`) and `getGlobalTransform()` (`p3d/scene/Container3D.ts:1654`).
- **Picking needs a camera inside a view:** `Raycaster.setFromCamera` uses `camera.view3d`, so portal and off-view cameras can't pick. Build the ray from the camera's own matrices instead. Intersections omit `face`, `faceIndex`, `uv` and `instanceId`.
- **One View3D:** the renderer keeps a single View3D and rebuilds it whenever `render()` gets a different scene. Alternating scenes (HUDs, portals, FBOs) would thrash. It needs a `Map<scene, View3D>`.
- **insertBefore:** the fix writes private fields (`_worldTransformDirty`) and calls `@internal` `View3D._attach`. Use the public route instead: splice the child back out, set `parent = null`, then `addChildAt(child, index)` (`p3d/scene/Container3D.ts:1064-1105`).
- **MeshBasicMaterial:** it maps to `FlatMaterial`, because `Material3D({ lit: false })` fails to compile on WebGL (`'calculateShadow' : no matching overloaded function found`). That's a pixi-3d bug.
- **Types:** there are 50 type errors. Args are required for `<mesh3D>`, there are no event props on pixi classes, `scale={2}` is rejected (no `setScalar`), `color` is typed as `number`, and pixi-3d's `Track` collides with HTML `<track>`.
- **Prototype patching** mutates pixi-3d globally (see blocker B5).

## 3. Recommended architecture

**Recommendation: keep r3f core vendored and unmodified in react-pixi-fiber, add pixi-3d as an r3f "support" module, and upstream a few small seam changes so it can later run on published `@react-three/fiber`.**

| Option                                                                                                                                                                                                                                                      | For                                                                                                                    | Against                                                                                                                                                                        | Verdict                 |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------- |
| **A. pixi-3d as an r3f support: core vendored unchanged now, upstream seam asks later**                                                                                                                                                                     | Proven with zero core edits. Parity stays automatic: re-sync core from r3f and re-run tests. Only the adapter is ours. | Ships a copy of r3f core until upstream exports a provider-taking entry. Relies on duck typing that r3f could change.                                                          | **Recommended**         |
| B. Fork r3f core                                                                                                                                                                                                                                            | Free to change anything                                                                                                | 10k lines that diverge. Every r3f fix has to be ported by hand. The spike shows there's nothing to change.                                                                     | Reject                  |
| C. A thin r3f-compatible layer (reimplement the reconciler, events and loop)                                                                                                                                                                                | Small, pixi-native                                                                                                     | Gives up the exact semantics (event ordering, priority, Suspense, Activity, HMR) that make parity worth having. More work than A for a worse result.                           | Reject                  |
| D. Hybrid: published `@react-three/fiber` with real three for math, pixi for scene and renderer (through the `renderer` factory prop, `scene`/`camera` props and `extend()`: `r3f/core/renderer.ts:104-110`, `configuration.ts:201,238`, `extend.ts:85-89`) | No vendoring. three's Raycaster and Vector math come free.                                                             | Downloads `three/webgpu` and keeps two math libraries in the bundle, which defeats the point of pixi-3d. `getThree()` still hands three objects to code that meets pixi nodes. | Keep as a fallback only |

Why A works: core reaches three only through `getThree()` (`r3f/core/three.ts:18-23`), `support.three` (`r3f/core/extend.ts:86-89`) and duck-typed flags (`isObject3D`, `isScene`, `isCamera`, `isBufferGeometry`, `isMaterial`, `isColor`, `set/copy/fromArray`). It never uses `instanceof`.

Layering inside react-pixi-fiber:

1. **The L1 surface goes on pixi-3d prototypes** (`isObject3D`, `uuid`, `add/remove`, `traverse`, `dispose`, `updateWorldMatrix`, ...). Every `Container3D` then works, including the ones pixi-3d builds itself, such as glTF nodes passed to `<primitive>`. Medium term, pixi-3d should ship this surface (section 6, item 1) so we stop monkeypatching.
2. **The L2/L3 alias catalog is subclasses under three's names**, with positional constructors and renamed props. It overrides pixi-3d's same-named classes (SphereGeometry, AmbientLight, ...), whose options-object constructors would silently ignore positional `args`.
3. **The renderer facade** keeps one View3D per detached scene root and a proxy camera per view.
4. **The entry** re-exports r3f core with a pixi provider and its own pixi-typed `RootState`/`ThreeElements`.

Upstream asks to r3f, all small:

- A `/core` export of `createRoot(canvas, provider)` and `Canvas` with a `provider` prop.
- An open `kind` union.
- Make `Environment` lazy or support-provided, so `Canvas` doesn't force three's addon paths into the bundle.
- Route `insertBefore` through a host `addChildAt`-style hook.
- Resolve `getThree()` per root from `state.internal.support`.

None of these block us. They only remove the vendored copy.

## 6. pixi-3d changes needed

Each item below could be filed as an issue. Items marked **bug** are defects found during the spike or the code review.

1. **Three-compat scene surface.** Add `uuid`, `traverse`, `traverseAncestors`, `getWorldPosition`, `updateWorldMatrix`, `lookAt(x, y, z)`, `dispose()` → `destroy()`, and `isObject3D`/`isBufferGeometry`/`isMaterial` flags, either natively or as an opt-in `@pixi/3d/three-compat` entry. Removes global monkeypatching. (S)
2. **Three-named math aliases** on `Vector2`, `Vector3`, `ObservableVector3`, `Quaternion` and `Matrix4`: `copy`, `setScalar`, `lerp`, `length`, `sub`, `add`, `multiplyScalar`, `clone`, `equals`, `project`, `unproject`, plus `isVector3`. (S–M) Done in react-pixi-fiber for now, as prototype patches the support installs.
3. **Optional `Mesh3D` geometry and material.** Skip drawing until both are set, and allow `skeleton` and morph targets to be set after construction (`Mesh3D.ts:204,396`). (M)
4. **Late-enabled material features.** Let `emissive`, `clearcoat`, `sheen`, `transmission`, `iridescence`, `specular` and `anisotropy` turn on and off after construction, and let `doubleSided`, `flatShading`, `fog` and `vertexColors` change at runtime, through the descriptor-dirty path texture slots already use. (M)
5. **Point and spot light `decay` exponent**, where 0 means no falloff. (M)
6. **Public multi-hit raycast:** `Container3D.raycast(ray, out[], recursive)` or `View3D.raycastAll`, returning `faceIndex`, face indices, `uv` and a local normal, with optional `material.side` culling. (M) Done in react-pixi-fiber for now: the Raycaster ports three's `Mesh.raycast` over the geometry's attributes.
7. **Bug: `intersectRayGeometry` ignores vertex stride**, so interleaved geometry mis-picks (`events/intersectRayGeometry.ts:66-84`, `geometry/Geometry3D.ts:678`). (S) react-pixi-fiber's Raycaster reads the stride itself.
8. **Bug: `Material3D({ lit: false })` fails to compile on WebGL** (`'calculateShadow' : no matching overloaded function found`). (S)
9. **BatchedMesh3D slot picking** (`instanceId`) and an InstancedMesh-shaped API with a fixed count and per-instance colour. (M) Done in react-pixi-fiber for now, but per-instance colour needs a twin of each material with an instance-data bit; shader bits per slot, or a built-in instance colour, would remove it.
10. **Public transform and camera flush:** `View3D.updateTransforms()` and `Camera3D.updateMatrices(aspect)`, so `projection`/`view` are current outside render. (S)
11. **Per-call render of a (root, camera) pair**, or let a node be visible from several views. (L)
12. **HDR (RGBE) LoadParser and equirect→cube conversion.** EXR as an optional add-on. (M–L) Done in react-pixi-fiber for now: an RGBE decoder and a GPU bake into cubes.
13. **Re-prefilter IBL when the environment source updates**, plus a CubeCamera helper that renders a hidden View3D into cube layers. (L) Done in react-pixi-fiber for now by baking a new source per change, which pixi-3d prefilters from scratch.
14. **Environment and background intensity, rotation and blurriness** on View3D. Blur can sample the existing prefiltered mips. (M) Done in react-pixi-fiber for now: baked into the lighting cube, and a background drawn behind the view.
15. **Per-texture UV transform** (repeat, offset, rotation, center) packed per material slot. (M)
16. **Model3D option to build joint `Container3D`s** that drive the Skeleton, so bones appear as nodes. (M) Done in react-pixi-fiber for now: `GLTFLoader` builds the joints and binds each with `Skeleton.bindContainerBone`; it reads the parsed file's `Scene3DSource._descriptor`, which a public descriptor would replace.
17. **Geometry groups and index sub-range draws**, for multi-material. (M)
18. **Euler rotation order** on `Container3D`. (S–M) Done in react-pixi-fiber for now: a node's `rotation` is replaced with an ordered `Euler` that writes the quaternion.
19. **Explicit view time** that overrides `performance.now()` for `uTime`. (S)
20. **Missing geometry generators:** circle, ring, octahedron, dodecahedron, lathe; tube and extrude need Curve/Shape. (M–L) Done in react-pixi-fiber for all but tube, extrude and shape, by porting three's generators.
21. **Optional BVH hit volume** through `IHitVolume3D`. (L)
22. **Optional GPU occlusion queries** on WebGPU. (L)
23. **Bug: normals under a sheared world transform.** The vertex templates divide each column of the model matrix by its squared length, which is the inverse transpose only without shear; a rotated child of an unevenly scaled parent is lit at the wrong angle. Pass a normal matrix per mesh, or work it out in the transform pass. (S)
24. **Bug: a material's shader change doesn't re-record the default passes' draws.** `Mesh3D.invalidate()` and `_invalidateDescriptor` rebuild a mesh's shader and pass entry, but the opaque and transparent passes aren't dirty hooks, so they keep replaying the draws recorded with the old shader and state. react-pixi-fiber calls `View3D._invalidateDrawCaches` for each view drawing the material. (S)
25. **A viewport-size camera uniform.** Sized points need the view's size in pixels in the vertex stage; react-pixi-fiber reads it from `uLightTileTransform` (16 tiles across, 9 down). (S)
26. **A light-loop option to visit lights a face turns away from.** three's toon shading reads its ramp's darkest level for them; `createLightingBit` skips them. (S)
27. **Opaque output at alpha 1.** The material templates premultiply by alpha in every alpha mode, so an opaque material with an `alpha` below 1 comes out darker; react-pixi-fiber sets `alpha` to 1 while a material is opaque. (S)
28. **Ambient sheen and three's anisotropic tangent frame,** for parity on `MeshPhysicalMaterial`. A DFG table in three's parameterization that material bits could sample would also let the standard material drop its analytic fit. (S–M)
29. **A public tone mapping and output transform:** let a view take a custom curve bit and an exact sRGB transfer function, and offer AgX and Neutral, so react-pixi-fiber needn't swap `View3D._toneMappingBit`. (S)
30. **Fog after the tone curve**, as an option, so the fog colour shows as authored; react-pixi-fiber swaps `View3D._fogBit` for one that mixes in a slot of its tone mapping bit. (S)
31. **A light-space shadow box** for directional lights (a camera-like frustum rather than a world box), and a per-light shadow map size. (M)
32. **Spot light penumbra as a smoothstep**, and a settable near plane for spot shadows. (S)
33. **Point light shadows** (a cube or dual-paraboloid map), area lights and spherical-harmonics light probes. (L)
34. **Morph targets kept on the CPU**, or a picking pass, so a morphed mesh picks in its pose. (M)
35. **sRGB texture formats for colour slots.** Upload colour maps as `rgba8unorm-srgb` and drop the shader's 2.2 decode, so the GPU decodes before it filters and builds mipmaps, as three does, and a texture's `colorSpace` decides whether it decodes at all. (M)
36. **Morph targets after the first renderer.** Keep a geometry's morph targets, or repack them, when a new renderer's store meets it, so a cached morphed model draws in a second canvas. (S)
37. **Backgrounds.** Draw a view's background when it has nothing else to draw, and leave an sRGB cube background out of tone mapping, as three does. (S)
38. **A material texture-slot hook.** An event or public method when a slot's texture changes, which the UV-transform tracking now gets by wrapping `_setTextureSlot`, `_deriveLayoutFromBits` and `destroy`. (S)
39. **Prefilter float environments into a float cube.** `generateIblSpecialCubemap` already takes `format`; the pipes call it with `rgb10a2unorm`, which clips radiance above 1. (S)
40. **Split-sum lobes as three r187 mixes them:** a dielectric lobe and a metallic lobe mixed by metalness, with diffuse taken from the dielectric lobe, in `iblBit`. (S)
41. **Draw a view into a layer of its target.** Passes rebind `session.defaultTarget` without the bind's `layer`, so a view can't draw into a cube face. (S)

Items 1–5 and 7–8 matter most for the first two phases.

## 8. Open questions

1. **Target audience:** existing r3f users migrating (which needs drei-lite and the three-shaped math API), or pixi-3d users who want a React layer (L1 plus pixi-native names is enough)? The answer decides how much of L3 and drei to fund.
2. Will pixi-3d accept a three-compat surface in core (section 6, items 1 and 2), or must it stay in react-pixi-fiber as prototype patches?
3. Will pmndrs accept a `/core` provider export and an open `kind` union? If not, the vendored copy is permanent; that's acceptable but should be decided.
4. What's the lighting parity bar: numeric match to three's physical units, or "looks right"? A calibration table needs reference renders.
5. Is the per-frame cost of alias getters, setters and Color facades acceptable on mobile? Benchmark it before committing to the facade-heavy L3 approach (the `benchy` skill fits).
6. How much of r3f's own test suite can run against the pixi support, given it mocks three/WebGL (`packages/fiber/__mocks__`)? That's the best automated parity check if it ports.
7. Should pixi and three roots be able to share a page? It needs upstream per-root `getThree()`.
8. Which pixi-3d native names should stay reachable in JSX when three aliases override them (`<sphereGeometry>` with options versus positional args)? One option is a `pixi` prefix or a separate catalog.
